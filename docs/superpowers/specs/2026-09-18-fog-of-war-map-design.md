# Fog of War карта — дизайн (MVP)

Дата: 2026-09-18

## Идея

Мобильное приложение (React Native / Expo) с реальной гео-картой, скрытой
туманом войны. Пользователь физически перемещается (GPS), и территория
вокруг него плавно "открывается" — как в open-world играх, а не грубыми
геометрическими фигурами. Прогресс открытия карты хранится в облаке и
привязан к аккаунту пользователя.

## Стек

- **React Native + Expo** (dev client, не Expo Go — нужен из-за нативных
  зависимостей Mapbox и Skia)
- **Mapbox** (`@rnmapbox/maps`) — базовая карта
- **react-native-skia** — canvas-оверлей для рендера тумана
- **expo-location + expo-task-manager** — фоновый и foreground GPS-трекинг
- **Supabase** — auth + Postgres, хранение прогресса открытия карты

## Архитектура

- **MapScreen** — Mapbox `MapView`, центрирование на пользователе.
- **FogOverlay** — Skia `Canvas` поверх карты, синхронизирован с той же
  проекцией/камерой. Рисует полупрозрачную тёмную заливку и "прожигает" в
  ней мягкие радиальные круги (blend mode destination-out) в посещённых
  точках — даёт органичный плавный край без сетки/полигонов.
- **LocationTracker** — сервис GPS: foreground-трекинг (пока приложение
  открыто) и background task (expo-task-manager) на переднем плане ОС
  (foreground service на Android, background location updates на iOS).
  Оба пишут точки в один и тот же ProgressStore.
- **ProgressStore** — локальный массив посещённых точек
  `{lat, lng, radius, ts}` (AsyncStorage) + очередь синхронизации с
  Supabase.
- **Supabase**: таблица `visited_points (user_id, lat, lng, radius,
  created_at)`, `auth.users` для аккаунтов.

## Данные и синхронизация

- Точки добавляются в ProgressStore только если пользователь сдвинулся
  дальше N метров от последней сохранённой точки (прореживание, чтобы не
  заваливать рендер и бэкенд).
- Батчевая запись в Supabase (раз в 10–15 сек или каждые 5 новых точек).
- При старте приложения — один запрос, подтягивающий все точки
  пользователя, сразу рисуем маску (восстановление прогресса на новом
  устройстве/после переустановки).
- Без realtime-подписки на MVP — не нужен live-мультиплеер, только
  подтягивание при входе в приложение.
- Между устройствами конфликтов нет — просто объединение множества точек
  по `user_id`.

## Фоновый GPS-трекинг

- **iOS**: permission "Always" (запрашивается вторым шагом после
  foreground-разрешения, с объясняющим экраном — так требует Apple).
  `Location.startLocationUpdatesAsync` с `deferredUpdatesInterval`;
  significant-location-change как fallback, если строгий режим
  недоступен из-за ограничений ОС.
- **Android**: обязателен foreground service с постоянным уведомлением
  ("Открытие карты активно"), плюс runtime permission
  `ACCESS_BACKGROUND_LOCATION` (запрашивается отдельным шагом после
  обычного).
- Настройка точности/частоты в профиле пользователя ("экономия батареи"
  ~50–100м между точками vs "точный" ~20–30м) — иначе фоновый GPS ощутимо
  сажает батарею.
- Рендер маски в реальном времени происходит только пока приложение
  открыто; фоновые точки просто копятся и дорисовываются при следующем
  открытии приложения.

## Обработка ошибок и edge cases

- Нет GPS/permission denied — баннер с просьбой включить геолокацию,
  карта остаётся видна (с уже открытыми зонами), не блокируем экран
  модалкой.
- Нет сети при синхронизации — точки остаются в локальной очереди,
  retry при восстановлении сети. Локальный рендер не зависит от сети.
- Холодный старт с большим объёмом точек — рендерим/учитываем только
  точки в текущем видимом вьюпорте, чтобы не тормозить Skia.
- iOS "заморозил" фоновую задачу — ожидаемое ограничение платформы, не
  баг; точки просто не пишутся, пока приложение не в фокусе достаточно
  долго.

## Тестирование

- Ручное тестирование на реальных устройствах (прогулка/поездка,
  включённый и выключенный экран) — GPS-симулятор не даёт реалистичной
  картины.
- Юнит-тесты для чистой логики: прореживание точек по дистанции,
  батчинг для синхронизации, восстановление маски из сохранённых точек.
- Skia-рендер и Mapbox-интеграция без автотестов — только визуальная
  проверка вручную.

## Вне рамок MVP (для следующих итераций)

- Realtime-синхронизация между устройствами.
- Кастомизация внешнего вида тумана/карты.
- Социальные функции, достижения, зоны интереса и т.п.
